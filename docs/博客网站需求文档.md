# Ash 静态博客网站需求文档

> 文档版本：0.1（需求确认稿）  
> 编写日期：2026-10-31  
> 项目状态：待确认，确认后进入开发  
> 参考项目：Fuwari（基于 Astro 的静态博客模板）

## 1. 项目概述

### 1.1 项目名称

- 网站名称：Ash
- 网站标语：不诱于誉，不恐于诽，率道而行，端然正己。
- 网站类型：个人非商业静态博客
- 目标读者：网友、校友
- 内容语言：简体中文
- 内容范围：技术文章、学习笔记、生活记录、摄影、随笔及项目记录等

### 1.2 建设目标

基于 Fuwari 源码进行二次开发，保留其日系、柔和、轻盈的整体风格，并补充友链、时间线、访问量、丰富动画和可关闭的樱花粒子效果。网站内容通过 GitHub 中的 Markdown 文件维护，由 Vercel 自动构建和托管。

### 1.3 非目标

第一版不建设登录、注册、评论、点赞、密码文章、邮件订阅、后台管理、支付、商品或其他商业功能；不嵌入 Bilibili、YouTube、音乐播放器等第三方媒体组件。

## 2. 技术与许可约束

- 基础框架：沿用 Fuwari 的 Astro 技术栈和现有组件体系。
- 样式系统：沿用项目当前 Tailwind CSS 方案，不另行引入重型 UI 框架。
- 包管理器：pnpm。
- Node.js 与 pnpm 版本应遵循所采用 Fuwari 版本的仓库要求，并在 `package.json` 中锁定。
- 搜索：优先沿用 Pagefind，在静态构建阶段生成全文索引。
- 内容来源：仓库内 Markdown 文件及本地图片，不依赖在线 CMS。
- 开源许可：保留 Fuwari 原项目的 MIT 许可证与版权声明；Ash 自有内容单独声明版权。
- 部署平台：GitHub + Vercel；生产分支默认为 `main`。

## 4. 视觉设计要求

### 4.1 整体风格

- 保持 Fuwari 的二次元、日系、清新和柔和视觉风格。
- 主色使用低饱和粉色，仅用于链接、选中态、进度、按钮强调和局部装饰，不允许页面大面积被粉色覆盖。
- 中文字体由开发阶段根据可读性选定，优先使用本地系统中文字体栈，避免依赖大陆访问不稳定的在线字体服务。
- 英文及代码相关文本使用 JetBrains Mono，并将字体文件本地化托管。
- 卡片、阴影、模糊和透明度遵循 Fuwari 现有设计语言，避免额外堆叠装饰。

### 4.2 头像与品牌素材

- 当前头像源文件：`source/001-ava.jpg`。
- 原图尺寸为 1080 × 1080，应生成适合网页使用的压缩版本，并保留原图。
- 第一版可使用文字站名“ASH”，暂不单独设计 Logo。
- favicon、默认文章封面和 Open Graph 默认图在开发阶段补充。

### 4.3 横幅与候选素材

- 首页保留大幅二次元横幅。
- 横幅从已审核素材池中随机选取；同一次页面会话内避免频繁闪烁或无意义切换。
- 候选图需统一裁切比例、最低分辨率和压缩格式，并针对桌面端与移动端设置合理焦点。
- 候选素材建议存放在 `public/assets/banners/candidates/`，审核通过后移动至正式素材目录。
- 每张网络素材必须记录来源、作者、许可、原始链接和获取日期；无法确认再使用许可的图片不得进入生产站点。
- 优先使用明确授权素材或后续生成的原创风格图片，避免直接上线来源不明的动漫版权图片。

### 4.4 主题与动画

- 支持浅色、深色和跟随系统三种模式。
- 主题选择持久化到浏览器本地存储。
- 保留并强化页面切换、卡片进入、悬停反馈和图片加载动画。
- 增加樱花粒子效果，提供独立开关；选择结果持久化。
- 移动设备或低性能场景下降低粒子数量，后台标签页暂停动画。
- 即使第一版不以无障碍为核心指标，也应尊重系统“减少动态效果”设置。

## 5. 首页需求

- 使用 Fuwari 推荐的响应式组合布局：文章流为主体，桌面端配合个人信息侧栏，移动端改为单栏。
- 个人信息区域显示头像、名称 Ash、标语、GitHub 与 Bilibili 图标链接。
- 每页显示 8 篇文章，使用页码分页。
- 文章卡片显示标题、摘要、发布日期、更新时间、分类、标签、阅读时长和字数。
- 文章存在 `cover_path` 时显示封面；未设置时不显示封面，不使用强制占位图。
- 支持置顶文章和精选文章；排序优先级为置顶状态、发布时间倒序。
- 侧栏可展示最近更新、分类、标签和随机文章入口；热门文章在访问量数据源确定后启用。
- 首页横幅随机选取已审核素材，并保证标题、导航和前景文字具有足够对比度。

## 6. 文章内容模型

### 6.1 Frontmatter 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | string | 是 | 文章标题 |
| `published` | date | 是 | 发布时间 |
| `updated` | date | 否 | 最后更新时间 |
| `description` | string | 是 | 列表摘要及分享描述 |
| `cover_path` | string | 否 | 文章封面路径 |
| `categories` | string[] | 是 | 允许多个分类 |
| `tags` | string[] | 是 | 标签列表 |
| `draft` | boolean | 是 | 草稿不参与生产构建和搜索索引 |
| `pinned` | boolean | 否 | 首页置顶 |
| `featured` | boolean | 否 | 精选文章 |
| `slug` | string | 否 | 自定义稳定链接；缺省时由文件名生成 |
| `lang` | string | 否 | 缺省为 `zh-CN` |
| `publish_at` | datetime | 否 | 定时发布时间 |

### 6.2 文章模板

```yaml
---
title: "文章标题"
published: 2026-10-31
updated: 2026-10-31
description: "用于文章列表和分享卡片的简短摘要。"
cover_path: "./001.png"
categories:
  - 算法
  - 数学
tags:
  - 快速幂
  - C++
draft: false
pinned: false
featured: false
slug: "matrix-fast-power"
lang: "zh-CN"
# publish_at: "2026-11-01T08:00:00+08:00"
---
```

- 项目应提供 `pnpm new-post <filename>` 命令生成上述模板。
- 命令自动填写当前日期、根据文件名生成 slug，并创建文章资源目录。
- 构建阶段校验字段类型、日期、重复 slug、无效封面路径及空分类。

## 7. 文章详情功能

- 自动计算中文字数和预计阅读时间。
- 显示发布时间和更新时间。
- 自动生成文章目录，并随阅读位置高亮当前标题。
- 标题自动生成锚点，并提供复制标题链接按钮。
- 支持上一篇、下一篇和相关文章推荐。
- 相关文章优先根据共同标签和分类计算。
- 文章底部显示作者信息与 `CC BY-NC-SA 4.0` 版权说明。
- 图片支持懒加载、尺寸声明、WebP/AVIF 优化、点击放大、灯箱浏览和图片说明。
- 不支持隐藏文章、密码文章、评论、点赞和分享按钮。

### 7.1 Markdown 能力

- GitHub Flavored Markdown。
- 数学公式：行内与块级公式。
- Mermaid 图表。
- 脚注、任务列表、表格和删除线。
- Note、Tip、Important、Warning、Caution 等提示块。
- GitHub 仓库信息卡片。
- 代码块语法高亮、行号、文件名、高亮指定行、复制按钮和长代码折叠。
- 外部链接应有安全属性，并显示一致的外链提示。

## 8. 分类、标签、归档与时间线

- 一篇文章允许属于多个分类。
- 分类和标签均提供独立列表页与详情页。
- 标签页提供标签云与普通列表两种视图，移动端默认普通列表。
- 分类、标签和年份均可作为搜索筛选条件。
- 归档页采用完整时间线，以年份分组并展示全部已发布文章。
- 自定义时间线与文章归档分离，用于记录个人经历、学习节点和网站事件。
- 时间线数据使用仓库内 YAML、JSON 或 Markdown 集合维护，支持日期、标题、正文、类型和链接字段。

## 9. 搜索与内容发现

- 使用静态全文搜索，索引标题、摘要、正文、分类和标签。
- 搜索结果高亮关键词，并显示标题、摘要、日期、分类和标签。
- 支持按分类、标签和年份筛选。
- 草稿及未来发布时间未到的文章不得进入索引。
- 提供最近更新、随机文章和相关文章。
- 热门文章依赖公开访问量数据，待访问量技术方案确认后启用。

## 10. 友链页面

- 友链数据通过独立配置文件维护，不写死在页面组件中。
- 每项支持名称、简介、头像、网址和可选标签。
- 失效头像使用本地默认图；外部链接在新标签页打开。
- 第一版不提供在线申请表单，新增友链通过修改仓库配置完成。

## 11. 访问量与统计

- 网站需要基础访问统计，并在文章详情显示访问量。
- 页面访问统计与公开文章访问量可能采用不同数据源，实施前需确认最终方案。
- 推荐默认方案：Vercel Analytics 用于站点分析，另使用轻量服务或 Vercel Serverless 存储公开文章计数。
- 计数应避免刷新一次即无限重复累计，并对失败请求静默降级，不阻塞正文渲染。
- 第一版不要求来源、热门页面、搜索词和性能监控面板。

## 12. 隐私与版权

- 隐私政策说明 Vercel 托管、访问统计、本地存储主题偏好与粒子效果偏好。
- 不收集邮箱、评论内容、账号信息等主动提交数据。
- 版权页区分网站程序、Ash 原创文章和第三方图片素材。
- Ash 原创文章默认采用 `CC BY-NC-SA 4.0`；另有声明的文章以单篇声明为准。
- 第三方素材必须保留所需署名，不得以本站文章许可覆盖素材原许可。

## 13. 内容迁移

- 当前已有两篇 Markdown，位于 `wiki/` 多级目录中。
- 迁移时保留正文、公式和代码块，并为每篇文章补充 Frontmatter。
- 推荐将目录层级映射为分类，例如“数学 / 数论”；具体标签按正文主题补充。
- Obsidian 风格内部链接（例如 `[[乘法快速幂]]`）需要转换为可构建的站内链接，无法解析时在构建检查中报告。
- 原始文件应在迁移确认前保留，避免覆盖导致内容丢失。

## 14. 发布与部署流程

- GitHub 目标仓库：`Ash-HYX/AshLab`，公开仓库，个人账号。
- 当前本地仓库分支为 `main`，尚无首次提交，且尚未配置远程地址。
- Vercel 项目尚未创建；开发完成后从 GitHub 导入仓库。
- 推荐流程：本地编写 Markdown → 本地检查与预览 → 提交并推送 → Vercel 自动构建生产版本。
- Pull Request 应生成 Vercel Preview，便于文章与页面发布前审查。
- GitHub Actions 执行格式检查、类型检查和生产构建。
- 定时发布推荐使用 `publish_at` + GitHub Actions 定时触发 Vercel Deploy Hook；发布时间以 `Asia/Shanghai` 为准。
- 自定义域名暂缓，第一版使用 Vercel 分配域名。

## 15. SEO 与索引策略

- 第一版不主动配置 Google、Bing 或百度站长平台，不提交搜索引擎。
- 用户暂不要求 RSS、Sitemap 和额外 robots 配置；若 Fuwari 默认生成 RSS，应提供配置开关并按确认结果关闭。
- 为社交分享自动生成文章 Open Graph 图片，使用文章标题、站名和可选封面。
- 草稿和未到发布时间的文章不生成公开页面，也不得出现在搜索、列表和分享元数据中。
- 即使不主动做 SEO，公开生产页面仍可能被搜索引擎发现；如要求完全不收录，需要另行启用全站 `noindex`。

## 16. 性能与兼容要求

- 支持近期版本的 Chrome、Edge、Firefox 和 Safari。
- 适配手机、平板、笔记本和桌面屏幕，重点检查 360px、768px、1280px 和 1920px 宽度。
- 图片默认懒加载并生成合理尺寸，首屏横幅除外。
- 字体、图标、脚本和核心样式尽量本地化，减少中国大陆访问时对境外第三方资源的依赖。
- 粒子特效不得阻塞页面交互；低性能设备自动降低效果质量。
- Vercel 在中国大陆的网络稳定性不作为可保证指标；第一版目标为前端资源优化和减少请求，若要求稳定低延迟需另行评估国内 CDN、域名备案与国内托管。
- 页面构建不得出现断链、无效资源、重复 slug 或 Frontmatter 校验错误。

## 17. 配置与维护要求

- 站名、标语、头像、导航、社交链接、主题色、横幅池和功能开关集中到配置文件。
- 非组件开发者应能仅修改配置和 Markdown 完成大部分日常维护。
- 提供中文 README，覆盖环境安装、启动、创建文章、图片管理、构建、部署和常见错误。
- 提供 Markdown 功能示例文章，但可设置为开发演示或草稿，不默认发布。
- 社交链接：
  - GitHub：`https://github.com/Ash-HYX`

## 18. 验收标准

1. `pnpm install`、检查命令和生产构建均成功完成。
2. 首页每页显示 8 篇文章，置顶、分页和可选封面行为符合要求。
3. 浅色、深色、跟随系统模式均正常，刷新后保留用户选择。
4. 樱花特效可关闭，刷新后保留选择，移动端无明显卡顿。
5. 文章模板可通过命令生成，非法字段能在构建阶段被发现。
6. 现有两篇 Markdown 成功迁移，公式、代码块和中文内容显示正确。
7. 数学公式、Mermaid、提示块、仓库卡片、增强代码块和图片灯箱均有示例验证。
8. 搜索可检索标题、摘要、正文、分类和标签，草稿不出现在结果中。
9. 分类、标签、归档、时间线、友链、关于、隐私、版权和 404 页面均可访问。
10. 桌面端和移动端不存在遮挡、横向溢出或无法操作的控件。
11. GitHub 推送后 Vercel 能自动部署，Pull Request 能生成预览版本。
12. 页面访问量失败时不影响静态内容访问。
13. 所有上线横幅均有可追溯来源和使用许可记录。
